# Contributing — bsgusa / bala-weave

End-to-end: find a repo → read its AGENTS.md → pick an issue → branch → PR.

## 60-second start

1. **Find a repo** in the `bala-nexus` world map that interests you.
2. **Read its `AGENTS.md`** — that's the local operating manual.
3. **Pick an issue** — look for `good first issue` or `help wanted` labels, or open one.
4. **Branch from `main`** — `git checkout -b your-description`.
5. **Make a small clear commit** — `feat(scope): description` or `fix(scope): description`.
6. **Open a PR** using the `bala-weave` PR template.
7. **Wait for review** — within 14 days (per `bala-voice` response-time promise).

## PR template fields

- **What** — one sentence: what this changes and why
- **Which repo** — the repo this PR targets
- **Connection** — which other repo or venture does this touch?
- **Checks** — branch from main, clear commit, tests pass, truthful claims, ROADMAP/backlog updated if scope changed

## Issue template fields

- **What** — one sentence: what you're proposing or reporting
- **Which repo** — the repo this relates to
- **Priority** — `[NOW]` / `[NEXT]` / `[LATER]` / `[PARKED]`
- **Connection** — which other repo or venture does this touch?
- **Next step** — what should happen next, and who can do it?

## Good-first-issue areas

- Documentation improvements in any repo
- Typos, broken links, clarity fixes in READMEs
- Adding a repo to the `bala-nexus` world map
- Translating a page or doc
- Writing a first test for a repo that lacks one

## Truthful-claims rule

No fabricated contribution metrics, response-time promises beyond `bala-voice`, or engagement numbers.

## Labels

`good first issue`, `help wanted`, `collab`, `trending-signal`, `NOW`, `NEXT`, `LATER`, `PARKED`
